# AI Daily Radar 🤖

گزارش روزانه فارسی از خبرهای هوش مصنوعی، مدل‌های زبانی و ویدیوهای مهم برای یک مهندس کامپیوتر. دو مسیر وجود دارد: مسیر پیشنهادی، استفاده از گزارش زمان‌بندی‌شده ChatGPT و ارسال آن به کانال با GitHub Actions است؛ مسیر مستقل قدیمی از مدل OpenRouter استفاده می‌کند.

## مسیر پیشنهادی: گزارش ChatGPT به تلگرام

برای راه‌اندازی و بررسی اتصال، [راهنمای ارسال گزارش ChatGPT به تلگرام](CHATGPT_TELEGRAM_FA.md) را بخوانید. در این مسیر به کلید مدل جداگانه یا سرور همیشه‌روشن نیاز نیست. **اتصال و انتشار واقعی تا پس از ثبت تنظیمات، تست بات و فعال‌سازی مسیر در وظیفه ChatGPT انجام نمی‌شود.** مخزن عمومی است و متن گزارش‌هایی که در آن ذخیره می‌شوند برای عموم قابل مشاهده است.

> پس از قرار گرفتن کد در ریپو، گزارش تا زمانی که تنظیمات و کلیدهای زیر را وارد نکرده‌اید فعال نیست. هرگز توکن بات و کلیدهای API را داخل چت، فایل‌های ریپو، اسکرین‌شات یا متن عمومی ارسال نکنید.

## خروجی چیست؟

بات منابع خبری و ویدیوهای انتخاب‌شده را بررسی می‌کند، متن مقاله یا زیرنویس قابل‌دسترس را می‌خواند و یک گزارش فارسی شامل نکته‌ها، اهمیت موضوع و لینک منبع می‌فرستد. محتوای گرافیک و طراحی هنری تا حد امکان حذف می‌شود؛ طراحی معماری مدل و سیستم‌های نرم‌افزاری در محدوده گزارش است.

- منابع اولیه شامل OpenAI، Anthropic، Google DeepMind، Google AI، Hugging Face و چند کانال آموزشی، مصاحبه و پژوهش در یوتیوب هستند. فهرست قابل‌ویرایش در [`sources.json`](sources.json) قرار دارد.
- اگر کلید اختیاری YouTube Data API تنظیم شود، جست‌وجوی موضوعی یوتیوب هم انجام می‌شود؛ بدون آن فقط کانال‌های موجود در فهرست بررسی می‌شوند.
- اگر متن ویدیویی قابل دریافت نباشد، سیستم نبود زیرنویس را اعلام می‌کند و درباره محتوای آن حدس نمی‌زند. برای ویدیوهای خیلی طولانی، اگر فقط بخشی پردازش شده باشد، گزارش آن را مشخص می‌کند.
- پیش‌فرض هر روز حداکثر ۶ خبر و ۲ ویدیو از ۴۸ ساعت گذشته است. انتخاب‌ها و منابع محدودند؛ این سیستم پوشش همه ویدیوهای یوتیوب یا همه خبرهای جهان را تضمین نمی‌کند.
- لینک مطالب ارسال‌شده ثبت می‌شود. اگر چند قسمت از گزارش لازم باشد و ارسال یک قسمت شکست بخورد، قسمت‌های ثبت‌شده مجدداً ارسال نمی‌شوند. قطع‌شدن دقیقاً بعد از پاسخ موفق تلگرام و قبل از ذخیره وضعیت همچنان می‌تواند یک پیام تکراری ایجاد کند.

خروجی، **خلاصه فارسی زیرنویس** است و متن کامل ترجمه‌شده ویدیو را منتشر نمی‌کند. خلاصه مدل زبانی ممکن است اشتباه باشد؛ لینک اصلی برای بررسی در هر مورد آورده می‌شود.

## مسیر مستقل جایگزین: GitHub Actions و OpenRouter

این بخش درباره برنامه مستقل قدیمی است، نه اتصال گزارش ChatGPT. برای جلوگیری از انتشار تکراری، زمان‌بندی خودکار آن به‌صورت پیش‌فرض غیرفعال است و فقط اجرای دستی دارد. اگر عمداً این مسیر مستقل را می‌خواهید، متغیر مخزن `ENABLE_LEGACY_RADAR` را برابر `true` قرار دهید و از فعال‌بودن هم‌زمان هر دو مسیر خودداری کنید.

این مخزن عمومی است؛ GitHub در حال حاضر اجرای Actions روی runner استاندارد برای مخزن عمومی را رایگان اعلام می‌کند. مدل پیش‌فرض `openrouter/free` نیز فقط به مدل‌های رایگان مسیریابی می‌شود. شرایط، سهمیه، دسترس‌پذیری، محدودیت منطقه و کیفیت سرویس‌های رایگان ممکن است تغییر کند.

برای جلوگیری از هزینه ناخواسته، گردش کار `FREE_ONLY=true` دارد و در این حالت یک مدل پولی یا ارائه‌دهنده ابری دیگر پذیرفته نمی‌شود. به حساب OpenRouter کارت یا پرداخت اضافه نکنید مگر اینکه خودتان بخواهید؛ سیستم با پایان سهمیه رایگان ممکن است تا بازنشانی سهمیه گزارش کامل تهیه نکند.

### ۱. ساخت کانال و بات تلگرام

1. در تلگرام یک کانال بسازید یا از کانالی استفاده کنید که مدیر آن هستید. برای تنظیم آسان‌تر می‌توانید یک نام عمومی مانند `@MyAIRadarChannel` انتخاب کنید.
2. به [`@BotFather`](https://t.me/BotFather) بروید، دستور `/newbot` را بفرستید و نام و شناسه بات را انتخاب کنید. توکن بات را فقط نزد خود نگه دارید.
3. در تنظیمات کانال وارد **Administrators** شوید، بات را اضافه کنید و اجازه **Post Messages** بدهید.
4. برای کانال عمومی، مقدار `TELEGRAM_CHAT_ID` همان `@نام_کانال` است. برای کانال خصوصی باید شناسه عددی آن را پیدا کنید؛ در این حالت برای راهنمایی اعلام کنید کانال خصوصی است.

### ۲. ساخت کلید مدل رایگان

1. در [OpenRouter](https://openrouter.ai/) حساب بسازید و از بخش API Keys یک کلید ایجاد کنید.
2. از مدل پیش‌فرض `openrouter/free` استفاده کنید و طرح رایگان و سهمیه فعلی حساب را بررسی کنید. ممکن است لازم باشد تنظیمات حریم خصوصی سرویس برای استفاده از ارائه‌دهندگان رایگان را در همان حساب فعال کنید.
3. کلید را در ادامه فقط به‌عنوان GitHub Secret وارد کنید. این برنامه متن منابع عمومی را برای خلاصه‌سازی به ارائه‌دهنده مدل انتخاب‌شده می‌فرستد؛ داده‌های محرمانه را به این منابع اضافه نکنید.

### ۳. ثبت امن تنظیمات در GitHub

در صفحه همین مخزن بروید به:

**Settings → Secrets and variables → Actions → New repository secret**

این سه Secret را بسازید:

| نام دقیق Secret | مقدار |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | توکنی که BotFather داده است |
| `TELEGRAM_CHAT_ID` | نام عمومی کانال، مثلاً `@MyAIRadarChannel`، یا شناسه عددی کانال خصوصی |
| `OPENROUTER_API_KEY` | کلید API حساب OpenRouter |

دو Secret زیر اختیاری‌اند، ولی برای پوشش بهتر توصیه می‌شوند:

| نام دقیق Secret | کاربرد |
| --- | --- |
| `YOUTUBE_API_KEY` | جست‌وجوی ویدیو در کل یوتیوب از طریق YouTube Data API، علاوه بر کانال‌های انتخاب‌شده |
| `SUPADATA_API_KEY` | دریافت جایگزین زیرنویس موجود، وقتی روش مستقیم از سرور GitHub موفق نیست |

برای `YOUTUBE_API_KEY` در [Google Cloud Console](https://console.cloud.google.com/) یک پروژه ایجاد کنید، **YouTube Data API v3** را فعال کنید و API Key بسازید. کلید را تا حد امکان به همان API محدود کنید. این API سهمیه دارد و سهمیه حساب خود را باید بررسی کنید.

برای `SUPADATA_API_KEY` می‌توانید حساب رایگان [Supadata](https://supadata.ai/) بسازید. طبق تعرفه فعلی سرویس، طرح رایگان تعداد محدودی اعتبار ماهانه دارد. این برنامه فقط حالت `native`، یعنی دریافت زیرنویس موجود، را استفاده می‌کند و تولید صوت‌به‌متن پولی را درخواست نمی‌دهد. سقف پیش‌فرض برنامه ۳ درخواست اولیه در روز و ۷۵ درخواست در ماه است؛ درخواست ناموفق برای زیرنویس نیز می‌تواند اعتبار مصرف کند. حتماً طرح و مصرف واقعی را در حساب سرویس بررسی کنید. این مسیر جایگزین است و اگر کلید نگذارید برنامه ابتدا روش مستقیم را امتحان می‌کند.

### ۴. آزمایش اتصال و ارسال

1. وارد تب **Actions** در مخزن شوید. در صورت درخواست GitHub، اجرای Actions را فعال کنید.
2. گردش کار **AI Daily Radar** را باز کنید و **Run workflow** را بزنید.
3. گزینه `check` را انتخاب و اجرا کنید. این مرحله اتصال بات، مجوز انتشار در کانال و پاسخ API مدل را بررسی می‌کند، اما پیامی به کانال نمی‌فرستد. اگر کلید YouTube هم قرار داده باشید، آن را نیز بررسی می‌کند. یک درخواست مدل و در صورت تنظیم، یک جست‌وجوی یوتیوب از سهمیه مصرف می‌شود.
4. برای دیدن شکل گزارش، یک بار با گزینه `preview` اجرا کنید و خروجی را در لاگ همان اجرا ببینید. پیش‌نمایش پیام نمی‌فرستد ولی از سهمیه مدل و در صورت نیاز، سرویس زیرنویس استفاده می‌کند.
5. برای ارسال فوری گزارش همان روز، گزینه `publish` را اجرا کنید. پس از ارسال موفق، اجرای دوباره همان روز گزارش را تکرار نمی‌کند.

**مخزن عمومی است:** لاگ‌های Actions و محتوای گزارش موجود در cache را اطلاعات عمومی فرض کنید. خودِ توکن‌ها در Secrets قرار دارند و داخل فایل وضعیت ذخیره نمی‌شوند؛ با این وجود هیچ کلید یا اطلاعات خصوصی را در منابع، متغیرهای معمولی، فایل‌های ریپو یا خروجی پیش‌نمایش قرار ندهید.

### زمان‌بندی و وضعیت

- در صورت فعال‌کردن `ENABLE_LEGACY_RADAR=true`، اجرای مستقل اصلی حدود **۰۹:۰۵ به وقت تهران** است و اجرای دوم حدود **۱۱:۰۵** برای تلاش دوباره در نظر گرفته شده است. این زمان‌بندی جدا از گزارش ChatGPT است.
- GitHub ممکن است اجرای زمان‌بندی‌شده را با تأخیر شروع کند. در مخزن عمومی، اگر تا ۶۰ روز فعالیتی در مخزن نباشد، GitHub ممکن است زمان‌بندی را غیرفعال کند؛ در تب Actions آن را دوباره فعال کنید.
- وضعیت گزارش و سهمیه‌های برنامه در GitHub Actions cache نگهداری می‌شود. Cache ذخیره‌سازی تضمین‌شده نیست و ممکن است حذف شود. پس از حذف آن، سابقه ارسال و شمارنده‌ها از دست می‌رود؛ بنابراین علاوه بر سقف نرم‌افزار، سهمیه حساب‌های سرویس را نیز کنترل کنید. تاریخچه پیام‌ها ممکن است پس از وقفه‌ای طولانی تکرار شود.
- در صورت خطا، وضعیت اجرا و متن خطا را در تب Actions ببینید. این پروژه در حال حاضر سرویس مانیتورینگ یا هشدار جداگانه برای خرابی ندارد.

## شخصی‌سازی

منابع و عبارت‌های جست‌وجوی یوتیوب در [`sources.json`](sources.json) قرار دارند. شناسه کانال یوتیوب باید شناسه `UC...` باشد. برای فید خبر، دامنه مقاله باید در `allowed_hosts` منبع آمده باشد. فیدهای شخص‌ثالث Anthropic برای پیدا کردن لینک استفاده می‌شوند؛ فقط لینک‌های دامنه رسمی Anthropic پذیرفته می‌شوند.

برای تغییر مقادیر بدون دستکاری کد، در **Settings → Secrets and variables → Actions → Variables** این متغیرها را اضافه کنید:

| Variable | پیش‌فرض | توضیح |
| --- | --- | --- |
| `MAX_ARTICLES` | `6` | حداکثر خبرهای انتخاب‌شده |
| `MAX_VIDEOS` | `2` | حداکثر ویدیوهای انتخاب‌شده |
| `MAX_TRANSCRIPT_CHUNKS` | `5` | حداکثر بخش متن هر ویدیو؛ بیشتر یعنی درخواست و زمان بیشتر |
| `MAX_LLM_CALLS_PER_DAY` | `32` | سقف تعداد درخواست‌های مدل این برنامه در روز، شامل preview و check |
| `SUPADATA_DAILY_CAP` | `3` | سقف درخواست زیرنویس جایگزین در روز |
| `SUPADATA_MONTHLY_CAP` | `75` | سقف درخواست زیرنویس جایگزین در ماه |

این سقف‌ها **سقف دلاری نیستند** و وضعیت آن‌ها به cache وابسته است. در طرح رایگان OpenRouter سهمیه به کل حسابتان تعلق دارد؛ استفاده از برنامه‌های دیگر هم روی آن اثر می‌گذارد. افزایش سقف‌های برنامه، سهمیه سرویس را افزایش نمی‌دهد.

برای تغییر ساعت اجرای GitHub، cronها را در [`.github/workflows/radar.yml`](.github/workflows/radar.yml) تغییر دهید. GitHub cron را با UTC اجرا می‌کند؛ ساعت‌های فعلی با UTC+03:30 تهران تنظیم شده‌اند.

## اجرای محلی یا Docker

فایل `.env.example` را به `.env` کپی کنید، دسترسی آن را محدود کنید و مقادیر خصوصی را فقط روی دستگاه خود بگذارید. با `FREE_ONLY=true` می‌توانید از OpenRouter رایگان یا مدل محلی سازگار با API استفاده کنید. استفاده از هر ارائه‌دهنده ابری دیگر نیاز به تغییر صریح `FREE_ONLY` دارد و ممکن است هزینه داشته باشد.

```bash
cp .env.example .env
chmod 600 .env
# فایل .env را در ویرایشگر امن روی دستگاه خودتان تنظیم کنید.
docker compose build
docker compose run --rm ai-radar python app.py check
docker compose run --rm ai-radar python app.py preview
docker compose up -d
docker compose logs -f ai-radar
```

برای Ollama، یک مدل نصب‌شده با توانایی مناسب در فارسی و خروجی JSON و نشانی سازگار مثل `http://host.docker.internal:11434/v1` لازم است. در Linux، Docker به `host-gateway` و قابل‌دسترسی‌بودن Ollama از داخل کانتینر نیاز دارد. `LLM_MODEL` را روی نام واقعی مدل محلی قرار دهید. نسخه محلی از ساعت موجود در `DAILY_TIME` استفاده می‌کند و پس از خطا تقریباً هر ۱۵ دقیقه دوباره تلاش می‌کند. برای روشن‌ماندن آن به دستگاهی روشن و شبکه متصل نیاز است.

## تست و محدودیت‌ها

```bash
python3 -m unittest discover -s tests -v
```

تست‌ها با داده و API شبیه‌سازی‌شده، انتخاب منابع، خطا، سقف‌ها، حالت رایگان، پیش‌بررسی دسترسی بات و ارسال تکراری را بررسی می‌کنند. برای اطمینان از عملکرد واقعی، مرحله `check` و سپس `preview` را با تنظیمات خودتان انجام دهید. دریافت زیرنویس مستقیم به سرویس‌ها و تغییرات یوتیوب وابسته است و از بعضی شبکه‌های ابری ممکن است ناموفق باشد. API رسمی دانلود زیرنویس یوتیوب معمولاً به مجوز ویرایش خود ویدیو نیاز دارد؛ روش مستقیم این پروژه یک کتابخانه غیررسمی است.
